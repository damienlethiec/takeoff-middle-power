# Security and code-quality audit

Audit of branch `audit-quality`, started from `965d35a` (25 Oct 2026). Scope: `src/`, `scripts/`, `index.html`, `vite.config.ts`, `.github/workflows/deploy.yml`, dependencies. Severity reflects this project: a static, single-player game with no backend, no accounts and no user-generated content.

**Ground rule for the fixes: no behaviour change.** After every commit:

- `npm run sim` is byte-identical to the golden output.
- A stronger fingerprint is also identical: every state, gauge view, card view, preview, situation report and debrief over 400 seeded games, hashed before and after.
- `npm test`, `npm run typecheck`, `npm run lint` and `npm run build` pass.
- The Playwright bot plays full games to an ending with no page errors and no `undefined`/`NaN` on screen. It ran against the dev server and against the production build with its CSP (`vite preview`).

Status: **Fixed** (in this branch), **Open** (recommended, not done), **OK** (checked, nothing to do).

## Security

| # | Sev. | Where | Finding | Status |

| S1 | Medium | `.github/workflows/deploy.yml` | **CI token exposure.** The workflow granted `contents: write` to every job. `actions/checkout` also saved that write token in `.git/config`, where any dependency's install script run by `npm ci` could read it. Third-party actions were referenced by moving tags (`@v4`), which their maintainer can re-point at any time. | **Fixed.** The workflow default is now `contents: read` and only the two publishing jobs get `contents: write`. Checkout uses `persist-credentials: false` in the deploy job (actions-gh-pages pushes with its own `github_token`). All actions are pinned to full commit SHAs, with the tag in a comment. Job timeouts added. |
| S2 | Low | `deploy.yml` "Show the link" | `${{ steps.target.outputs.url }}` was interpolated inside a `run:` script. It is not exploitable today, because the slug is reduced to `[a-z0-9._-]`. But it is the pattern behind script injection. | **Fixed:** the value goes through an `env:` variable. The branch name was already read from `$GITHUB_REF_NAME` / `env.BRANCH`, never interpolated into a script. `commit_message: "Deploy ${{ github.ref_name }}"` is an action input passed as an argument, not shell, so it is safe. |
| S1b | Low | `deploy.yml` | GitHub warns that `actions/checkout` and `actions/setup-node` v4 target the deprecated Node 20 runtime; they are forced onto Node 24 and still work. | S4 | Medium | `index.html` | **No Content-Security-Policy.** Every screen is built with `innerHTML` from template strings. A CSP is the safety net if one interpolation is ever left unescaped. | **Fixed:** `vite.config.ts` injects a `<meta http-equiv="Content-Security-Policy">` into the **production build only**, right after the charset. GitHub Pages cannot send headers, so the policy has to be a meta tag. Policy: `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'none'`. ## Accessibility

Checked: interactive elements, focus, ARIA, contrast of the colour tokens, reduced motion.

Good already: gauges, cards, choices and controls are real `<button>`s. There is a global `:focus-visible` outline, modals have `role="dialog"`, `aria-modal` and a label, and focus moves into each modal. The clock speed buttons use `aria-pressed` and the phase is announced politely. Text contrast is high: muted text is 5.8–7.3:1 on the dark panels, paper-muted is 4.8:1, the primary button is 9.7:1. A `prefers-reduced-motion` block stops CSS animations, and `wait()` and the tipping animation shorten too.
